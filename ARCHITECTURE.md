# Архитектура userspace-интеграции

**Русский** | [English](ARCHITECTURE.en.md)

`S99awg3` → `amneziawg-go -f opkgtunN` → TUN ядра.
`awg setconf` передаёт параметры по Unix-сокету
`/var/run/amneziawg/opkgtunN.sock`. Модуль amneziawg.ko не загружается.
NDMS-объект `OpkgTunN` связывает интерфейс с настройками прошивки.

## Состояние

- /opt/etc/awg3/managed.tsv: профиль, индекс, имя NDMS, разделитель TAB.
- /opt/etc/awg3/enabled: разрешение запуска при загрузке Entware.
- /opt/etc/awg3/watchdog-enabled: отдельное разрешение watchdog.
- /var/run/awg3/running: служба запущена в текущей загрузке.
- /var/run/awg3/opkgtunN.pid: PID проверяется по /proc/PID/exe и cmdline.
- /var/run/awg3/service.lock: сериализация start/stop/repair/save/install.
- /opt/etc/awg3/conf/parsed: производные файлы с закрытыми правами.

Удаление профиля не освобождает индекс автоматически: запись и объект остаются,
чтобы не переиспользовать номер с чужой политикой. Для удаления старой привязки
нужна отдельная ручная операция после проверки маршрутов.

Существующий неизвестный интерфейс никогда не удаляется и не захватывается.
При повторной загрузке NDMS может восстановить наш постоянный TUN. Разрешено
подключение к нему только при наличии записи managed.tsv, признака tun_flags
в sysfs и типа OpkgTun в NDMS. Занятую TUN-очередь ядро открыть не позволит.

## Запуск и остановка

up сначала проверяет все файлы и обязательные зависимости. Владение номером
сохраняется атомарно до настройки, чтобы ошибка не потеряла запись.
Затем создаётся NDMS-объект, запускается движок, передаются AWG-параметры,
применяются IP/MTU/DNS и поднимается интерфейс. Конфигурация автоматически
не записывается во flash: для этого существует save.

stop убирает признак running, останавливает watchdog и опускает свои интерфейсы.
Процессы TUN остаются живы для сохранения интерфейсов и привязок.
Это не полноценный rollback маршрутизации: политика без VPN может перейти на
WAN, если такой резерв явно разрешён её настройками.

Обновлять движок поверх работающего процесса запрещено. Перед обновлением
нужны disable и перезагрузка; после неё установщик делает резервную копию файлов.
Невозможность выполнить один шаг не означает автоматическое восстановление
всей сетевой конфигурации; ошибка возвращается вызывающему.

## Watchdog

Проверяет доступность UAPI; при отказе вызывает repair с интервалом не менее
180 секунд. Исправный интерфейс не перезапускается из-за давности handshake.
Watchdog не является проверкой доступности VPN-сервера или внешнего Интернета.
Запускается только после ручного enable и при наличии running.

## Профили

Синтаксическая проверка, допустимые поля, IPv4/CIDR, MTU, имена интерфейсов;
отдельные временные файлы с umask 077. В shell-команды попадают лишь проверенные
IP/числовые значения. AWG-ключи передаются как данные, не исполняются.
Криптографическую и протокольную корректность значений окончательно проверяет
сам awg. При его отказе статус службы — ошибка; настройки до этого шага
могли частично примениться.

IPv6 и несколько peer не поддерживаются текущей NDMS-обвязкой.
Скрипт prepare_profile.py создаёт отдельную IPv4-копию по явному флагу
--ipv4-only; исходник никогда не перезаписывается.

## Маршрутизация и доступность

Парсер не создаёт default route даже при AllowedIPs=0.0.0.0/0. Существующие маршруты не удаляются. Выбор full-tunnel или IP-списка — отдельная настройка NDMS. Ping Check назначается и сохраняется через NDMS по docs/HEALTHCHECK.md; UAPI-watchdog не заменяет проверку Интернета.
