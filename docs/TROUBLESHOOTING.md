# Диагностика

**Русский** | [English](TROUBLESHOOTING.en.md)

| Симптом | Проверка |
|---|---|
| SSH Connection refused на 222 | На тестовом роутере Entware SSH на 22. Используйте свой фактический порт. |
| SSH оборвался после reboot | Подключитесь заново ssh -p 22 root@192.168.1.1. |
| curl.exe: not found | Команда Windows попала в SSH. Введите exit или откройте новую вкладку PowerShell. |
| Handshake есть, данных нет | Разные клиентские профили для ПК/роутера; Endpoint через провайдера; проверить реальные ping и HTTPS. |
| Зелёная точка, сайты не открываются | Настройте Ping Check и проверьте передачу данных, а не только состояние интерфейса. |
| VPN первым, пропал интернет | Верните провайдера первым, проверяйте одно устройство в отдельной политике. Fallback ещё не гарантирован. |
| Приоритет VPN вернулся после reboot | Был сохранён такой приоритет. save NDMS и enable службы — разные операции. |
| Нет default route в full-tunnel | Настройте его явно по ROUTING. Для выборочных IP он не нужен. |
| ip: invalid argument 29999 to table | На устройстве BusyBox ip, большие номера таблиц не принимаются. Не подставляйте случайный номер без проверки занятости. |
| iptables: not found | Наличие NAT не определяется наличием утилиты в Entware. Используйте диагностику прошивки. |
| Unknown symbol crypto_chacha_init | Старый модуль .ko несовместим. В проекте используется userspace, модуль не нужен. |
| NDMS вернул ошибку при exit code 0 | Проверяйте и текст, включая error[код]. Скрипты релиза это учитывают. |
| Ping Check argument parse error | Сначала отдельная команда создания профиля. |
| Ping Check has no assigned profile | Сначала привязка, потом no ping-check restart. |
| Установщик отказывается обновлять движок | disable и reboot: обычный stop сохраняет процесс TUN. |

## Минимальный набор — SSH

```sh
/opt/etc/init.d/S99awg3 status
ndmc -c "show ping-check"
ip -4 route show table all
ip -4 rule show
```

Ранняя сборка status показывала HeaderProtectionKey. Перед публикацией её вывода используйте `... status | sed '/header protection key:/d'`. В релизе поле скрыто. Не публикуйте showconf, приватные профили, полный running-config и необработанные логи. Статус также может содержать ваши публичные IP и ключи.

Успешный ping роутера может идти через провайдера. Проверка компьютера с включённым VPN-приложением проверяет другой туннель. Оба случая приводили к неверным выводам при первоначальной настройке.

## Память

```sh
free
p=$(cat /var/run/awg3/opkgtun0.pid)
grep -E '^(Name|VmRSS|VmHWM|VmSize|Threads):' "/proc/$p/status"
```

Подставьте свой индекс. VmRSS — текущая резидентная память; VmHWM — максимум с запуска; VmSize — виртуальное адресное пространство, не расход RAM.

Единичное наблюдение NC-1012: RSS 47168 KiB (~46 MiB), HWM 231748 KiB (~226 MiB), 16 потоков, доступно системе ~233 MiB, swap не использовался. Это не гарантия расхода и не нагрузочный тест. Сравнивайте RSS при похожей нагрузке; утечка не установлена.

## service.lock

Замок не перехватывается автоматически. Не удаляйте замок живой службы. Проверьте PID и процесс; при возможности прервать VPN отключите автозапуск и перезагрузитесь. Service: started — маркер запуска, не доказательство работоспособности каждого туннеля.
