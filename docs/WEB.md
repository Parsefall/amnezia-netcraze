# Веб-панель на роутере

**Русский** | [English](WEB.en.md)

Панель v0.8.0 работает на **самом роутере** через Entware. Компьютер/телефон нужен только как браузер. Это отдельный адрес HTTPS, а не карточка встроенного раздела «Приложения» Netcraze. В интерфейсе есть русский и английский языки.

Возможности: импорт .vpn/.txt/.conf или ключа, замена существующего профиля, запуск/остановка всей VPN-службы, автозапуск, watchdog/inbox, время handshake, счётчики трафика, настройка и просмотр PingCheck, фильтрованный журнал, восстановление резервной копии, смена пароля панели. Маршруты и политики устройств остаются в штатном интерфейсе прошивки.

## Установка поверх работающего проекта

Требуются Entware и уже установленный Amnezia Netcraze. Для нового роутера сначала выполните [установку VPN](../INSTALL.md); импорт профиля затем можно сделать через панель. Проверенная ранее аппаратная конфигурация: Netcraze Giga NC-1012, hw 1210C000, aarch64, NetcrazeOS 5.1.5, kernel 4.9-ndm-5. Запуск панели v0.4.1 подтверждён владельцем на этом роутере; новая форма PingCheck пока проверена только на имитации прошивки.

1. Скачайте `awg3-netcraze-arm64-userspace.tar.gz` из [релиза v0.8.0](https://github.com/Parsefall/amnezia-netcraze/releases/tag/v0.8.0). В PowerShell на ПК, из папки с архивом:

```powershell
scp -O -P 22 .\awg3-netcraze-arm64-userspace.tar.gz root@192.168.1.1:/opt/tmp/
ssh -p 22 root@192.168.1.1
```

2. Далее **в SSH shell роутера**, не в PowerShell:

```sh
opkg update
opkg install python3-light python3-codecs python3-openssl python3-email python3-urllib python3-logging openssl-util ca-bundle
mkdir -p /opt/tmp/awg3-v040
tar -xzf /opt/tmp/awg3-netcraze-arm64-userspace.tar.gz -C /opt/tmp/awg3-v040
sh /opt/tmp/awg3-v040/awg3-userspace/router/install-web.sh
```

Пакеты Python разделены в [Entware ARM64](https://bin.entware.net/aarch64-k3.10/), поэтому одной установки python3-light для HTTPS-панели недостаточно. pip и сторонние Python-библиотеки не нужны. Установщик проверяет импорт модулей и контрольные суммы, обновляет скрипты импорта, сохраняет резервные копии, устанавливает панель. VPN-движок и существующие профили не заменяются, маршруты не меняются, VPN не перезапускается.

3. Задайте **свой пароль панели** (12–128 символов) и адрес домашней сети:

```sh
/opt/bin/python3 /opt/lib/awg3/web/server.py --setup --bind 192.168.1.1 --network 192.168.1.0/24 --port 8088
/opt/etc/init.d/S101awg3-web enable
```

Пароль вводится дважды скрыто; это отдельный пароль, не пароль root или веб-интерфейса Netcraze. Если LAN имеет другой адрес/маску, замените оба значения. Слушать `0.0.0.0` или публичный адрес запрещено. Порт 8088 должен быть свободен; при конфликте используйте другой порт выше 1023.

4. Откройте **https://192.168.1.1:8088**. Разрешён доступ с адресов указанной подсети. Вход по домену/CrazeDNS не поддерживается: проверяется точное соответствие IP и порта.

Сертификат создаётся локально и самоподписан, поэтому браузер покажет предупреждение о доверии. Сверьте SHA256-отпечаток сертификата с выведенным при настройке и доверяйте ему только при совпадении. Повторно вывести отпечаток:

```sh
/opt/bin/openssl x509 -in /opt/etc/awg3/web/cert.pem -noout -fingerprint -sha256
```

Панель предназначена для домашней сети: не настраивайте проброс порта/публичный reverse proxy. Фильтрация по подсети не заменяет разделение доверенных и гостевых устройств на самом роутере. Сертификат действует 825 дней; для перевыпуска повторите setup, задайте пароль и перезапустите панель.

## Обычная работа

- Откройте «Туннели → ⚙» нужного туннеля, выберите файл или вставьте ключ и нажмите «Проверить и применить». Новый туннель добавляется кнопкой «Добавить туннель», в том числе при работающих остальных туннелях.
- Импорт сохраняет OpkgTun, маршруты, политики и приоритет. Ограничения экспорта и поведение отката описаны в [роутерном импорте](ROUTER-IMPORT.md). DNS из профиля не применяется, IPv6 удаляется, отсутствующий MTU становится 1280.
- После переноса сервера проверьте новый handshake, PingCheck и трафик. Доступный движок не означает исправное VPN-соединение. Правило до старого Endpoint при наличии нужно обновить отдельно.
- Общие кнопки в «Настройках» управляют **всей службой**; кнопки на карточке туннеля управляют только им. «Выключить» в автозапуске снимает только автозапуск.
- Восстановление резервной копии применяется к её прежнему профилю. Ключи и файлы резервных копий через панель не скачиваются.
- Журнал фильтрует строки с ключами и длинные строки, похожие на секреты; это диагностический просмотр, а не полный экспорт лога. Не публикуйте диагностику без собственной проверки.
- Панель имеет отдельный автозапуск; остановка VPN её не выключает. Сессия длится один час. Смена пароля завершает все сессии.

## Управление и восстановление доступа

```sh
/opt/etc/init.d/S101awg3-web status
/opt/etc/init.d/S101awg3-web restart
# Отключить только панель и её автозапуск:
/opt/etc/init.d/S101awg3-web disable
# Включить обратно:
/opt/etc/init.d/S101awg3-web enable
```

Забытый пароль/смена LAN: остановите панель, повторите `--setup` с нужным адресом и подсетью, затем запустите её через `enable`. Это перевыпускает сертификат. Обновление той же версии установщиком сохраняет существующие пароль и LAN-настройки. Конфигурация и приватный TLS-ключ лежат в `/opt/etc/awg3/web/`, журналы запуска — `/opt/var/log/awg3-web.log`. Не публикуйте папку web с настройками. Общий `uninstall.sh` отключает также панель, сохраняя данные.

## Проверки и ресурсы

14 автоматических тестов HTTPS/API: авторизация, cookie, Origin/Host/CSRF, домашняя подсеть, ограничение попыток входа и размера запроса, завершение сессии, безопасные команды, импорт и временные файлы, восстановление, фильтрация секретов, смена пароля. NDMS/движок имитируются. Браузерный тест в Edge проверил вход, обзор, импорт, восстановление, RU/EN, мобильную ширину 390 px и выход без ошибок JavaScript. HTTPS отдельно проверен настоящим TLS-соединением в тестах; браузерный макет использовал локальный тестовый HTTP.

Панель держит один Python-процесс постоянно, максимум 8 одновременных обработчиков; это дополнительный расход памяти. Цифры RSS/CPU на NC-1012 **ещё не измерены**, лёгкость по сравнению с конкретными приложениями не заявляется. Проверить после установки:

```sh
p=$(cat /var/run/awg3/web.pid)
grep -E '^(Name|VmRSS|VmHWM|Threads):' /proc/$p/status
```

Браузер опрашивает состояние раз в 15 секунд только на видимой вкладке. CDN, аналитики и внешних ресурсов нет. Backend выполняется от root ради управления VPN; наружу доступны только фиксированные действия, без shell и произвольных команд. Пароль хранится как PBKDF2-SHA256 с солью, 600000 итераций; cookie HttpOnly/Secure/SameSite=Strict, CSRF-токен, проверка Host/Origin, TLS 1.2+. Это не заявление об отдельном внешнем аудите безопасности.


## Исправление nohup: not found в 0.4.0

Установка зависимостей и настройка пароля/сертификата не требуют повторения. Замените только `/opt/etc/init.d/S101awg3-web` версией из 0.4.1 и выполните `chmod 755` и `S101awg3-web enable` с полным путём. Теперь используются встроенные возможности shell; устанавливать nohup не нужно. Присланный журнал подтвердил эту ошибку на NC-1012; запуск исправленной версии на устройстве ещё ожидает подтверждения.

## PingCheck через панель (v0.7.0)

Откройте **Туннели → ⚙ → PingCheck** нужного туннеля и нажмите **Включить / применить**. Рекомендуемые значения: `1.1.1.1`, интервал 10 с, тайм-аут 3 с, 3 неудачи, 2 успеха. Поля — шаблон новой настройки; текущее состояние выбранного туннеля показано над ними. Изменённые поля не сбрасываются при автообновлении.

Проверка работает средствами прошивки в режиме ICMP, без перезапуска интерфейса. Панель создаёт отдельный профиль для выбранного VPN и не редактирует общий профиль провайдера. «Отключить проверку» снимает назначение только с выбранного VPN. При ошибке выполняется попытка вернуть прежнее назначение; если откат не подтверждён, панель сообщает об этом. Маршруты и приоритеты не меняются.

После успешного применения дождитесь `status: pass`. Нажмите **Сохранить конфигурацию роутера**, чтобы сохранить изменения после перезагрузки. Эта кнопка сохраняет **всю текущую конфигурацию прошивки**, включая другие несохранённые изменения. Без неё применение действует только в текущей конфигурации.

Проверка сбоев и отката покрыта тестами с имитацией прошивки. Настройка через новую форму и реальное переключение при обрыве VPN пока не проверены на устройстве. `pass` не доказывает работоспособность резервирования; оно зависит и от политик/маршрутов. Ранее эти CLI-команды и состояние `pass` проверены на Netcraze Giga NC-1012, NetcrazeOS 5.1.5.

## Управление и имена (v0.7.0)

«Управление службой» запускает и останавливает всю VPN-службу. Карточки «Туннели» показывают отдельные профили. Кнопки запуска и остановки недоступны, когда соответствующее действие не требуется. Отключение автозапуска не останавливает VPN; для остановки используйте «Остановить».

«Подключено» означает: служба запущена, движок отвечает и PingCheck этого интерфейса показывает `pass`. «Отключено» — служба остановлена, движок недоступен или PingCheck показывает `fail`. Пока результат отсутствует, отображается «Связь не проверена». Состояние обновляется каждые 15 секунд, дополнительно к задержке самой проверки. Успешная проверка одного адреса не гарантирует доступность всех сайтов.

«Переименовать» меняет отображаемое имя в панели и описание интерфейса Netcraze. Поддерживаются 1–64 символа: латиница, цифры, пробел, точка, дефис, подчёркивание. Файл профиля и идентификатор OpkgTun не меняются; для последующего импорта используйте прежнее имя файла. Имя сохраняется в `/opt/etc/awg3/names/` и восстанавливается при запуске службы. Подпись типа `connection-type.OpkgTun` в штатном интерфейсе не изменяется.

## Несколько туннелей (v0.7.0)

- **Обзор**: только название и состояние каждого туннеля.
- **Туннели → Добавить туннель**: задайте уникальное имя латиницей, загрузите `.vpn`/`.txt`/`.conf` или вставьте ключ и нажмите «Создать и запустить». Остальные туннели продолжают работать. Для каждого нужен отдельный клиентский ключ Amnezia; одинаковые ключи отклоняются.
- **⚙ у туннеля**: переименование, замена ключа, резервные копии выбранного профиля, его PingCheck и удаление. Цель замены зафиксирована: выбрать другой туннель в форме нельзя.
- **Запустить / Приостановить** на карточке действуют только на этот туннель. Пауза сохраняется на накопителе, переживает перезагрузку и учитывается watchdog. Импорт в приостановленный туннель не запускает его. Общий запуск службы сохраняет индивидуальные паузы; возобновляйте туннель его кнопкой.
- **Журнал** содержит только журнал. Общие кнопки службы, автозапуск, watchdog, пароль и сохранение конфигурации прошивки находятся в **Настройках**.

Каждый туннель получает отдельный `OpkgTunN` и процесс AmneziaWG. Интерфейсы доступны для назначения политик и маршрутов в Netcraze. Панель не добавляет маршрут по умолчанию и не назначает устройства автоматически. Настройте маршруты и PingCheck каждого туннеля, проверьте доступность, затем сохраните конфигурацию прошивки. Общая кнопка сохранения сохраняет также другие несохранённые изменения роутера.

Удаление требует подтверждения. Оно останавливает только выбранный туннель, завершает проверенный процесс и удаляет его интерфейс прошивки; другие туннели не перезапускаются. Приватная копия остаётся в `/opt/etc/awg3/backups/deleted/`. При отказе удаления профиль остаётся для повторной попытки, обычно на паузе. После успешного удаления нажмите **Настройки → Сохранить конфигурацию роутера**. При необходимости отдельно поправьте свои политики и статические маршруты.

Удалённые имена и индексы остаются зарезервированы в `managed.tsv`, чтобы старые ссылки на интерфейс не достались другому VPN. Выберите новое имя при повторном создании. Пространство индексов — 0–99, включая зарезервированные; не редактируйте резервирование без проверки внешних ссылок. Каждый дополнительный userspace-туннель потребляет память и CPU; безопасное количество на NC-1012 ещё не измерено.

Если создание сохранило профиль, но запуск отклонён прошивкой, панель покажет ошибку и оставит профиль для настройки, повторного запуска или удаления. Работу нескольких туннелей проверяли на имитаторе; на физическом NC-1012 она пока не испытана.

## Обновление из панели (v0.8.0)

Один раз установите v0.8.0 обычным способом через `router/install-web.sh`. На роутере должен быть пакет доверенных сертификатов:

```sh
opkg update
opkg install ca-bundle
```

Затем откройте **Настройки → Обновление приложения → Проверить обновления**. Панель покажет установленную и последнюю стабильную версию из `Parsefall/amnezia-netcraze`. Нажмите **Обновить** и подтвердите выбранную версию. Компьютер не скачивает пакет: всё выполняет роутер. Проверка GitHub происходит только по нажатию кнопки.

Этапы: скачивание, проверка архива и всех файлов, резервная копия, установка, перезапуск панели и проверка HTTPS. Пока идёт обновление, изменение туннелей и настроек заблокировано. После перезапуска страница перезагрузится; войдите прежним паролем. Профили, приватные ключи, сертификат, пароль, имена, паузы, автозапуск и маршруты не заменяются. Сами туннели не перезапускаются; watchdog кратковременно останавливается на время замены скриптов.

Кнопка обновляет панель, импортёр и управляющие скрипты. Если бинарники `awg`/`amneziawg-go` в релизе отличаются от установленных или изменился формат установки, обновление будет отклонено **до замены файлов**: требуется ручная процедура. Понижение версии и повторная установка той же версии кнопкой не выполняются.

Требуется доступ роутера к GitHub по HTTPS, корректное время, установленные зависимости панели и свободное место на накопителе `/opt` (начальная проверка требует не менее 48 МиБ, затем проверяется место для резервной копии). Архивы ограничены по размеру, ссылки и небезопасные пути в tar запрещены, SHA256 проверяется перед установкой. Загружается только готовый пакет из Releases этого проекта, не произвольная ссылка и не скрипт из ветки main.

Если новая панель не запускается или запись файлов завершается ошибкой, обновлятор пытается восстановить прежние файлы и запустить старую панель. Копия и журнал находятся в `/opt/etc/awg3/updates/job-*/backup/` и `worker.log`; последний результат виден в блоке обновления. Скачанный архив и временная распаковка удаляются после завершения, резервные копии остаются.

Отключение питания/SIGKILL во время замены файлов не гарантирует автоматический откат. После такого прерывания установка блокируется до ручного восстановления. Не удаляйте активные `update.lock` или `service.lock`. При восстановлении через SSH сначала убедитесь, что указанные в них PID уже не работают; используйте сохранённый `backup/files.json` с контрольными суммами и копии файлов. Конфигурацию VPN и папку `web/settings.json` восстанавливать из обновления не требуется — обновлятор их не меняет. При ошибке проверки сети проверьте время, доступ к GitHub и `ca-bundle`; проверка TLS не отключается.

Проверены загрузка метаданных GitHub, тесты установки/отката на временной файловой системе и интерфейс в браузере. Само обновление на физическом NC-1012 пока не испытано.
