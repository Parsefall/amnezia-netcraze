# Ping Check: проверка трафика через VPN

Зелёный интерфейс и свежий handshake не гарантируют доступ к Интернету. Watchdog пакета проверяет доступность локального UAPI, не доставку пакетов. Для доступности подключения применяется штатный Ping Check NDMS.

## Проверенная последовательность

Замените OpkgTun0 на свой интерфейс. Команды выполняются в **SSH shell роутера**. Сначала `ndmc -c "show ping-check"`: не заменяйте уже настроенный чужой профиль без понимания его назначения. Для нескольких туннелей используйте разные имена профилей.

```sh
ndmc -c "ping-check profile AWG3Check"
ndmc -c "ping-check profile AWG3Check host 1.1.1.1"
ndmc -c "ping-check profile AWG3Check mode icmp"
ndmc -c "ping-check profile AWG3Check update-interval 10"
ndmc -c "ping-check profile AWG3Check timeout 3"
ndmc -c "ping-check profile AWG3Check max-fails 3"
ndmc -c "ping-check profile AWG3Check min-success 2"
ndmc -c "interface OpkgTun0 ping-check profile AWG3Check"
ndmc -c "interface OpkgTun0 no ping-check restart"
```

**Создание профиля отдельной первой командой обязательно.** Иначе тестовая прошивка возвращала `argument parse error`. Команда `no ping-check restart` идёт **после привязки**, иначе получается `has no assigned profile`.

Не продолжайте после ошибки. Через 30–60 секунд:

```sh
ndmc -c "show ping-check"
```

На NC-1012 получены `name: OpkgTun0`, `ignore-fail: no`, `status: pass`, растущий successcount и failcount: 0. После проверки:

```sh
ndmc -c "system configuration save"
```

Интервал 10 секунд, таймаут 3 секунды, пороги 3 неудачи и 2 успеха. Это не обещание переключения ровно через 30 секунд. Отказ единственной контрольной цели также может признать туннель недоступным. Проверяйте адрес за туннелем: доступность самого Endpoint через провайдера не доказывает работу VPN.

## Границы проверки

На реальном роутере **проведена только успешная проверка**; владелец отложил искусственный отказ. Не подтверждены цвет индикатора при сбое, отсутствие ложного успеха через WAN, переключение клиентского трафика и восстановление после отказа. Проверять нужно все эти свойства, сохраняя локальный доступ и заранее подготовив восстановление VPN.

Не опускайте TUN как единственный тест: это проверяет административное выключение, а не зависание живого интерфейса. Не останавливайте общий удалённый VPN-сервер ради проверки одного клиента.

Для резерва провайдер должен быть разрешён политикой. **Эксклюзивные статические маршруты запрещают обход.** Проверьте отдельно, деактивируются ли импортированные маршруты при провале Ping Check. Наличие status: pass не гарантирует failover произвольной таблицы маршрутов.

## Снять привязку

```sh
ndmc -c "interface OpkgTun0 no ping-check profile AWG3Check"
```

Подставьте свои имена, проверьте show ping-check, затем сохраните конфигурацию. Профиль можно оставить неиспользуемым.
