# Интеграция с маршрутизацией роутера

**Русский** | [English](ROUTING.en.md)

Приложение создаёт отдельный интерфейс `OpkgTunN` для каждого туннеля. Его можно использовать в штатных настройках подключений, маршрутов и политик доступа роутера.

Создание и запуск туннеля не назначают ему устройства и не добавляют маршрут по умолчанию. Выберите нужный туннель в интерфейсе прошивки и настройте использование подключения средствами роутера. Поле AllowedIPs в профиле AmneziaWG не заменяет настройку маршрутизации прошивки.

Замена ключа в настройках существующего туннеля сохраняет его идентификатор и привязки. После удаления туннеля проверьте связанные с ним настройки прошивки. После изменения сетевой конфигурации сохраните её средствами роутера.

Приложение работает с IPv4; маршрутизация IPv6 через VPN не реализована. Настройки DNS из импортируемого через панель экспорта не применяются автоматически.

Для контроля связи настройте [PingCheck](HEALTHCHECK.md) отдельно для каждого туннеля.

## Резервный туннель (0.10.0)

В панели откройте **Туннели → ⚙ → Резервный туннель**, выберите другое подключение и нажмите **Сохранить резерв**. IP, сайты и привязки устройств по-прежнему задаются в интерфейсе Netcraze. Панель читает существующие правила роутера: переносить списки в неё не требуется. Выбор сохраняется на накопителе автоматически.

Оба туннеля должны быть запущены, иметь отдельные клиентские ключи и назначенный PingCheck. Резерв должен разрешать нужные сети в AllowedIPs; для DNS-маршрутов и политик требуется `0.0.0.0/0`. Неизвестный статус проверки не считается успехом. При `fail` основного фоновый обработчик выбирает резерв с `pass`; ручная пауза или остановка всей службы не считаются аварией. При `pass` основного в течение 30 секунд исходные правила возвращаются. Проверка выполняется раз в 10 секунд и не зависит от открытой вкладки браузера, но служба панели должна работать.

Обработчик временно меняет интерфейс назначения в существующих правилах, сохраняя сети, объектные группы и флаги `auto`/`reject`. Поддерживаются:

- `ip route … OpkgTunN` (IPv4-хосты, сети и явно заданный default route);
- `ip policy NAME route … OpkgTunN`;
- `dns-proxy route object-group NAME OpkgTunN`;
- `ip policy NAME permit global OpkgTunN order N` (с сохранением порядка остальных подключений).

Это не универсальный перехват пакетов на интерфейсе: неявная основная политика только с глобальными приоритетами, политики без явного порядка, маршруты через дополнительный IP-шлюз, IPv6, пользовательские iptables/ip rule и другие неизвестные формы правил автоматически не переключаются. Неизвестная форма правила, ссылающегося на переключаемый туннель, останавливает применение с сообщением об ошибке. Проверка результата подтверждает конфигурацию прошивки, но не доставку пакетов клиентов.

Сами движки и PingCheck при переключении не останавливаются. Новые соединения используют резерв; уже установленные TCP/UDP-сеансы могут оборваться при смене внешнего адреса. Если оба туннеля недоступны, возвращаются исходные правила: поведение при отказе (в том числе разрешённый ранее выход через провайдера) определяется их настройками. Для запрета обхода используйте штатные эксклюзивные маршруты.

Настройки пары находятся в `/opt/etc/awg3/failover.json`, временные изменения — в закрытом `/opt/etc/awg3/failover-journal.json`. Журнал содержит только затронутые правила, без VPN-ключей. Он записывается до изменения прошивки и сохраняется при неподтверждённом откате. После перезапуска обработчик восстанавливает прерванную операцию; при штатной остановке панели временные правила возвращаются. Не удаляйте журнал вручную.

Чтобы убрать резерв, выберите **Без резерва** и сохраните. Перед изменением задействованных правил в Netcraze отключите резерв: внешнее изменение правила во время переключения блокирует автоматический откат, чтобы не затереть вашу правку. Во время активного резерва не сохраняйте конфигурацию через веб-интерфейс прошивки: это закрепит временные правила. Кнопка сохранения в нашей панели в этот момент заблокирована на API. Перед удалением туннеля или отключением его PingCheck уберите связанные назначения резервов.

Проверки отказа, цепочек, восстановления, ошибок команд и перезапуска выполнены на модели прошивки. На физическом NC-1012 новая функция ещё не испытана.
