# Amnezia Netcraze

**Русский** | [English](README.en.md)

Доступна [веб-панель на самом роутере](docs/WEB.md): импорт файлов/ключей, управление VPN и PingCheck, состояние и резервные копии через браузер.

Можно импортировать `.vpn` или ключ из `.txt` **непосредственно на роутере**, а затем обновлять профиль загрузкой файла в папку inbox. См. [роутерный импорт и обновление](docs/ROUTER-IMPORT.md).

AmneziaWG 3.1 на Netcraze через Entware: готовый ARM64-пакет, userspace-движок и интеграция с маршрутизацией роутера. Без загрузки модуля `amneziawg.ko`.

**Проверено только на конкретном Netcraze Giga NC-1012 владельца проекта:** аппаратная ревизия `1210C000`, ARM64 (`aarch64`), прошивка **5.1.5 / 5.01.C.5.0-0**, Linux **4.9-ndm-5**, Entware на накопителе и `/dev/net/tun`. Совместимость с другими моделями и прошивками не заявляется.

Есть файл `.vpn` или ключ `vpn://`? Используйте [офлайн-конвертер с графическим окном](docs/CONVERTER.md), чтобы получить router.conf. Подписки без встроенного AWG-профиля требуют экспорта из личного кабинета.

## Скачать и установить

1. Скачайте `awg3-netcraze-arm64-userspace.tar.gz` и `.sha256` из [Releases](https://github.com/Parsefall/amnezia-netcraze/releases/latest).
2. Создайте **отдельного клиента Amnezia для роутера**. Один профиль нельзя одновременно использовать на ПК и роутере.
3. Выполните [пошаговую установку](INSTALL.md): копирование по SCP, одна команда установщика, импорт своего профиля.
4. Выберите [схему маршрутизации](docs/ROUTING.md). Для выборочных сайтов оставьте провайдера первым и импортируйте IP-маршруты на VPN.
5. Настройте [Ping Check](docs/HEALTHCHECK.md), проверьте работу и включите автозапуск.

Установщик проверяет контрольные суммы, сохраняет заменяемые файлы и **не запускает VPN, не импортирует ключи и не меняет приоритеты подключений**. Запуск VPN также не добавляет маршрут по умолчанию: решение о маршрутах принимает пользователь.

## Что проверено

На указанном устройстве подтверждены запуск движка, handshake, передача данных с роутера, DNS и HTTPS с компьютера в отдельной VPN-политике. После перезагрузки движок запустился автоматически; дальнейшая диагностика подтвердила передачу данных. Схема «VPN первым для всего роутера» вызывала потерю доступа — причина полностью не установлена, она не рекомендуется как первоначальная настройка.

Штатный Ping Check привязан к OpkgTun0 и успешно проверяет туннель. **Реальное переключение при отказе и последующее восстановление пока не испытаны.** Финальные изменения скриптов релиза проверены локально, но не переустановлены на тестовый роутер. Подробности: [VALIDATION.md](VALIDATION.md).

## Ограничения

- Один peer и один IPv4-адрес на профиль. IPv6 через VPN не настраивается.
- AllowedIPs задаёт допустимые адреса внутри AWG, а не создаёт маршруты NDMS.
- Это маршрутизация устройств и IP, а не отдельных приложений Windows.
- IP-списки CDN охватывают сторонние сайты и устаревают. Личные списки маршрутов не входят в релиз.
- Watchdog следит за локальным процессом, а Ping Check — за передачей трафика. Это разные задачи.
